# media/ — icons, fonts and the built-in base sets

Two unrelated things: application icons at the top level, and the base sets OpenTTD ships with in [baseset/](baseset/).

## Application icons

`openttd.svg` plus rasterisations from 16px to 2048px, `openttd.32.bmp` (used as the in-game window icon), XPM variants for X11, and `openttd.desktop` for freedesktop menus. Platform-specific icon containers live elsewhere — `.icns` for macOS and `.ico` for Windows are in [../os/](../os/).

## baseset/

| Contents | Notes |
| --- | --- |
| `openttd.grf`, `orig_extra.grf` | OpenTTD's own sprites — GUI icons, signals, autorail overlay, one-way arrows, canals. **Generated**, see below |
| `*.obg` / `*.obm` / `*.obs` | Base-set *metadata* for graphics / music / sound: `orig_dos`, `orig_dos_de`, `orig_win`, `orig_tto`, plus `no_music` and `no_sound` fallbacks |
| `OpenTTD-Sans/Serif/Mono/Small.ttf` | The bundled fonts; see [OpenTTD-font.md](baseset/OpenTTD-font.md) |
| `opntitle.dat` | The title-screen savegame |

The `.obg`/`.obm`/`.obs` files describe base sets, they do not contain them: they list the expected files and their MD5 checksums, plus a translated description for every language. The originals themselves come from a Transport Tycoon Deluxe install or from a free set such as [OpenGFX](../opengfx-8.0/CLAUDE.md).

## The GRFs are generated, and that bites

`openttd.grf` and `orig_extra.grf` are compiled from the `.nfo` + `.png` sources in [baseset/openttd/](baseset/openttd/) and [baseset/orig_extra/](baseset/orig_extra/) by **GRFCodec and NFORenum**. But they are also **committed to git**, because most developers do not have those tools installed.

The consequence, spelled out in [../COMPILING.md](../COMPILING.md): if CMake finds GRFCodec, it will regenerate the `.grf` files *into the source directory*, and different GRFCodec versions produce byte-different output. A build can therefore leave your working tree dirty with binary changes you did not make.

If that happens and you were not intentionally working on the graphics, clear `GRFCODEC_EXECUTABLE` and `NFORENUM_EXECUTABLE` from the CMake cache and `git checkout` the `.grf` files.

The `.grf.hash` files next to them are written by `grfid -m` and hold the GRF's MD5. They are not a build-freshness marker — they are consumed when generating the `.obg` metadata, which has to state the checksum of the `orig_extra.grf` it expects. Regenerate the GRF and you must commit the updated `.hash` alongside it.

The `.obg`/`.obm`/`.obs` files in the build tree are themselves generated by `cmake/scripts/Baseset.cmake` from the sources here plus every file in [../src/lang/](../src/lang/CLAUDE.md) — that is where the per-language `description.xx_YY` lines come from. So the checked-in metadata is a template, and translated descriptions arrive from the language files at build time.

Actually changing a sprite means editing the `.png` (8bpp, DOS palette) and its `.nfo` sprite definitions, then rebuilding with the tools present, and committing both the sources and the regenerated `.grf` and `.grf.hash`.
